The portal installs on the Zebra PDAs as an app. **Chrome menu (⋮) → Add to
home screen** → launcher icon, opens with no browser chrome, nobody types the
URL. The in-app prompt lives in the **menu drawer** (only on touch pointers,
only when not already installed).

**No service worker, on purpose.** Chrome dropped that requirement for menu
install in v108 (mobile). A worker would need a scope covering `/logistics`,
but Frappe serves the app's `public/` at `/assets/logistics_portal/` — whose
scope is `/assets/...` — so widening it needs a `Service-Worker-Allowed` nginx
header this app can't ship. The cost is only that `beforeinstallprompt` never
fires, so the card shows manual instructions instead of a one-tap button.

**Two manifest rules that silently break install** (both confirmed against the
spec, not assumed):
1. `scope` **must end in a slash**. Matching is a string prefix, not a path
   walk — bare `/logistics` also matches `/logistics-anything`.
2. `start_url` **must sit inside `scope`**, or the manifest is invalid. Ours is
   `/logistics/home` (the role resolver, so each role lands on its own screen).

Files: `logistics_portal/public/manifest.webmanifest`, `icon-192/512/maskable-512.png`,
linked from `logistics_portal/templates/pages/logistics.html`.
Icons are generated by a PIL script from the app's accent gradient + the
scan-frame glyph — the wordmark (244×47) is unreadable at 48dp.
`theme-color` is kept in step with the theme toggle by `composables/useTheme.js`.

**PDA sizing:** `@media (pointer: coarse)` in `index.css` enforces 44px touch
targets — it reaches handhelds and phones and leaves mouse-driven desks alone.
The language pills leave the 52px top bar below `sm` and reappear full-size in
the drawer. All nine floor screens verified at 320px: zero horizontal overflow.
