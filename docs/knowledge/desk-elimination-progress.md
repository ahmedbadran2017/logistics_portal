**DESK LOCK enforced 2026-08-24 (`8b7241c`):** Ahmed's directive — the team falling back to the raw Desk (/app) on a portal hiccup, hand-editing docs and bypassing portal guards, was creating worse data problems (a firefighting loop). Chose a **request-layer block, NOT role stripping**: blocking Desk in Frappe needs EVERY role to be desk_access=0, but the 6 team users (only 6: manager/packer/returns/2×dispatcher/picker, all System Users, keyed by the custom User field `custom_logistics_role`) carry roles they need (Raven chat, Employee Self Service, Stock/Delivery/etc.) whose DocPerms are ALSO what let the portal + codx save on their behalf. So `api/deskguard.block_desk_for_portal_team` (a `before_request` hook, verified live in this Frappe) redirects any user with `custom_logistics_role` set away from /app → /logistics, touching zero roles/permissions; fail-open. Emergency Desk = a separate admin account with no custom_logistics_role, OR grant the per-user `Logistics Desk Override` role (desk_access=1, created via after_migrate `ensure_desk_override_role`) — revoke to re-lock, no deploy. Note found during this: prod `All` role shows desk_access=1 but Frappe ignores it (Accountant/JoyAgent System Users with only desk_access=0 roles are correctly Desk-blocked). Deploy = migrate + restart.
