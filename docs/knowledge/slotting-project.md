Ahmed wants a portal page that reads zones/shelves + stock + order movement and re-organizes products by location for fast physical picking. Framed it as **velocity slotting (ABC) + pick-path**, 3 phases:
- **Phase 1 — analysis (read-only) — BUILT 2026-08-24 (`7df026c`):** `logistics_portal/api/slotting.py` (`overview` = scorecard + class table + per-zone A/B/C/cold heat, cached 1h; `movers` = drill list per class with current shelf + pick count) + `frontend/src/pages/Slotting.vue` at `/logistics/slotting`. Velocity = Pick List Item pick-lines over a rolling window (30/90/180d); ABC by cumulative pick share (80/15/5); placement = primary (max-qty) shelf per item from Bin (shelf regexp `^[A-Z][0-9]{1,2}[A-Z]?[.]? - JM`). Gated manager+dispatcher; nav under Inventory (added `layout-grid` icon use). Deploy = restart only.
- **Phase 2 — target layout + move worklist — BUILT 2026-08-27 (`4c906ae`):** Ahmed resolved the old blocker by decree — "the physical floor re-arranges to MATCH the plan, not vice versa". Fixed roles in `slotting.py ZONE_ROLES`: **E+G (65 bins) = fast wall for the 322 A-movers** (already the 2 hottest aisles, held 83 A-movers → fewest moves); **H+J+F (127 bins) = B zone**; **A+B+C+D+I (164 bins) = C long tail**; **X reserved** (exchanges); **AG (164) + BAB (108) racks + SLOW ZONE = high-stock reserve feeding the fast wall** (Ahmed 2026-08-27: SLOW ZONE means bulk-overflow store, NOT cold storage — cold/dead stock destination is still an open decision). Endpoints: `target_plan()` (roles+capacity+per-class compliance, cached 10 min), `move_list(cls)` (SKUs outside target letters, hottest first, suggested letter balanced by SKUs-per-bin fill). UI: Slotting page role cards + compliance bars + move worklist; Move button deep-links `MoveStock?item=&target=` (MoveStock pre-loads the item, shows target letter as hint).
- **Phase 3 — pick-path ordering + drift maintenance (NOT built):** a fixed shelf walk-order to sort pick lists; alert when a SKU's class no longer matches its location. With roles now fixed, walk order can be E→G→H→J→F→A→B→C→D→I once Ahmed confirms physical adjacency.

**Key measured findings 2026-08-24 (90d):** 31,552 pick-lines over 3,525 SKUs. **ABC: A=322 SKUs drive 80% of ALL picks, B=1,625, C=1,578.** The 322 A-movers are **scattered across 10 of 11 zones** (E60/J50/G35/A30/H24...) — the core inefficiency. Topology: 11 zones (A–J + X), 249 stocked shelves, low fragmentation (3,094 items on exactly 1 shelf). **COLD stock: 1,895 of 3,238 stocked SKUs (59%) had ZERO picks in 90d, occupying 140 of 249 shelves + 4,182 units** — prime space wasted. Pick-path avg = 1.68 zones/pick-list (max 10). Item groups are weak taxonomy (mostly 'All Item Groups'/'Final Group').

**Physical zone model (Ahmed, 2026-08-27 — authoritative):** lettered aisles = FAST ZONE (~a week of cover for EVERY live product, fed from SLOW or from Receiving); SLOW ZONE = bulk store feeding fast (biggest stock); Receiving Zone = new stock intake; Return Zone = returns intake; Sorting Zone = order prep. ABC map = arrangement WITHIN the fast zone, not separate zones. `overstock_list()` (2487296) = the reverse worklist: faces holding >2 weeks cover (cold items free the whole facing) → Move Stock deep-link with SLOW ZONE + excess qty pre-filled.
