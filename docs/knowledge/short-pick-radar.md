**The problem, measured 2026-09-30 (30 days):** 2,748 "Short pick:" comments on 628 orders; worst single order `#259117` short-picked **62×** in 6 days (then #259453 55×, #259928 44×). Outcome of the 628: 458 moved on, **170 still pending**, **0 cancelled**. On **152** of them the SAME item reported "not on the shelf" later shipped on that same order via a Delivery Note → the piece was in the building. That is a FLOOR not a rate: -ex / J- orders ship with no DN (see [orders-without-delivery-notes](orders-without-delivery-notes.md)), so the DN test cannot see them.

**Where the evidence lives:** `picking.report_short_pick` pulls the order off the draft list, calls `short_shelf.mark(item, bin, qty)` (site default `lp_short_shelf`, expires after `shortPickCooldownH` = 24h, cleared by a Stock Reconciliation hook), stamps `SO.custom_short_picked_at`, and writes a Comment `Short pick: item (<code>) not found on the shelf by <user> — pulled off <PL>; …` (+ `STILL IN THE TOTE` when pieces were deferred). The comment is the only per-ORDER, per-ITEM, repeat-counted record — `_ITEM_RE` / `_WHO_RE` parse 1,336/1,336 of them.

**Built (commit `8bc8b03`, `short_shelf.radar` + `short_shelf.rule`, page `ShortPicks.vue` at `/short-picks`, manager + dispatcher):** per (order, item) on orders still Pending — times, first/last, picker, pick list, tote flag, whether the order is back on a draft list, and the ledger bin by bin classed `pick` (pickable_condition minus ee veto) or `zone` (stock_moves._movable_condition but not pickable). Verdict: `ready` (free on a pickable bin → picker probably wrong) / `zone` (needs a move) / `nostock` (ledger agrees). On prod, 14-day window: 117 open pairs = 27 ready / 7 zone / 83 nostock.

**Ruling = a Comment `Short pick check: present|missing — item (<code>) …`** — no new doctype. A pair counts as checked only if its latest check is NEWER than its latest report, so a fresh short pick re-opens it automatically. `Short pick check:` does NOT match the `Short pick:%` LIKE used by the report counter / `seed_from_comments`, so rulings never inflate the repeat count. "present" clears the shelf hold for the item in ALL bins and busts `lp_pick_avail`/`lp_board_summary`/`lp_consolidation`; if no pickable free stock exists it returns `needsCount` rather than pretending the order is ready.

**Related false-"Ready" class — Product Bundle edited after orders were placed (found 2026-10-01):** "JUSTYOL Top 5 Box" (`9486746779902`) was edited 2026-09-26 15:39 — component `45820014362878` swapped for `45779741180158`. Orders keep their Packed Items from order time, the portal (correctly) reads Packed Items and shows them Ready, but pick-list creation (ecommerce_integrations / ERPNext, not this repo) rejects any order whose packed composition differs from the CURRENT bundle: old-composition orders picked 686 before the edit vs 1 after; new-composition 187 after. 13 old-composition orders were stuck (#261869 … #262361, J-008924). Fix options: Update Items on the SO (test on ONE first — unverified that it re-explodes), or never edit a live bundle (create a new bundle item instead).
